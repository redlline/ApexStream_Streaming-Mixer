# ApexStream — справочник REST API

Полное описание API микшера. Пригодится для интеграции с аппаратными пультами
(Bitfocus Companion, Touch Portal, Elgato Stream Deck), автоматизации из
скриптов и внешних систем расписания.

Все примеры — рабочие команды `curl`, их можно вставлять как есть, подставив
свой адрес и ключ.

---

## 1. Два способа обращаться к API

| Способ | Адрес | Авторизация | Когда использовать |
|---|---|---|---|
| **Напрямую к агенту** | `http://<агент>:8500` | заголовок `X-API-Key` | пульты, скрипты, внешние системы |
| **Через панель** | `https://<панель>/api/...` | cookie сессии | из браузера, где оператор уже вошёл |

Для пультов и автоматизации используйте **прямой доступ к агенту** — он не
требует сессии и логина.

```bash
curl -s http://10.0.0.10:8500/api/ping -H "X-API-Key: ВАШ_КЛЮЧ"
# {"ok":true,"time":"2026-07-26T19:30:00"}
```

Ключ агента лежит в `agent.env` (переменная `API_KEY`) на самом сервере агента.

> **Безопасность.** Ключ даёт полный контроль над эфиром. Порт 8500 не должен
> торчать в интернет — держите его в локальной сети или за VPN. Панель (порт
> 8080) — единственное, что имеет смысл публиковать наружу, и только по HTTPS.

### Ответы и ошибки

Всё возвращается в JSON. Параметры передаются как `multipart/form-data`
(в `curl` — флаг `-F`), кроме отдельно отмеченных случаев.

| Код | Что означает |
|---|---|
| `200` | успех, тело — JSON (обычно `{"ok":true}`) |
| `400` | неверные параметры (текст причины в поле `detail`) |
| `401` | неверный или отсутствующий `X-API-Key` |
| `404` | объект не найден (поток, баннер, шаблон) |
| `409` | действие невозможно сейчас (например, движок не ответил) |

## 2. Быстрый старт: самые нужные команды

Ниже `KEY` — ваш API-ключ, `A` — адрес агента, `1` — id потока.

```bash
KEY="ВАШ_КЛЮЧ"; A="http://10.0.0.10:8500"

# что вообще есть и что в эфире
curl -s $A/api/streams -H "X-API-Key: $KEY"

# запустить / остановить поток
curl -s -X POST $A/api/streams/1/start -H "X-API-Key: $KEY"
curl -s -X POST $A/api/streams/1/stop  -H "X-API-Key: $KEY"

# показать баннер №5 на 15 секунд
curl -s -X POST $A/api/streams/1/play -H "X-API-Key: $KEY" \
     -F banner_id=5 -F duration=15 -F fade=1

# запустить полноэкранный ролик №2
curl -s -X POST $A/api/streams/1/playvideo -H "X-API-Key: $KEY" -F video_id=2

# снять ролик досрочно
curl -s -X POST $A/api/streams/1/stopvideo -H "X-API-Key: $KEY"

# показать HTML-шаблон №3 на 20 секунд
curl -s -X POST $A/api/streams/1/playhtml -H "X-API-Key: $KEY" \
     -F template_id=3 -F duration=20 -F fade=1
```

## 3. Служебные

| Метод | Путь | Параметры | Описание |
|---|---|---|---|
| GET | `/api/ping` | — | проверка живости и время сервера |
| GET | `/api/sysstat` | — | CPU, память, диск, GPU, аптайм |
| GET | `/api/mediamtx/status` | — | состояние обоих инстансов MediaMTX |
| POST | `/api/mediamtx/start` | — | запустить MediaMTX |
| POST | `/api/mediamtx/stop` | — | остановить MediaMTX |
| GET | `/api/srtpush/info` | — | параметры приёма SRT-push (порт, шаблоны строк) |
| GET | `/api/logs` | `stream_id` (0), `limit` (200) | журнал процесса и событий |
| GET | `/api/settings` | — | настройки агента |
| POST | `/api/settings` | JSON-тело | сохранить настройки |

`/api/srtpush/info` возвращает готовые шаблоны — подставьте `{host}` (адрес
агента) и `{id}` (ваш streamid):

```json
{"enabled":true,"running":true,"srt_port":8890,"rtsp_port":8554,
 "publish_tpl":"srt://{host}:8890?streamid=publish:{id}",
 "input_tpl":"rtsp://127.0.0.1:8554/{id}"}
```

Энкодер пушит по **SRT**, а поток читается из MediaMTX по **RTSP**. Так
сделано намеренно: SRT-выход MediaMTX отдаёт не всякий кодек, и вещательный
MPEG-2 (обычное дело для Astra и аппаратных энкодеров) по нему не читается —
путь заводится и числится `ready`, но чтение падает с `Input/output error`.
По RTSP тот же поток читается нормально, H.264 тоже.

## 4. Потоки

### Список и состояние

```bash
curl -s $A/api/streams -H "X-API-Key: $KEY"
```

В каждом потоке есть блок `status` — это **живое состояние процесса**, а не
запись в базе:

| Поле | Смысл |
|---|---|
| `running` | движок реально запущен |
| `playing` / `playing_left` | идёт показ баннера/HTML и сколько секунд осталось |
| `ad_playing` | в эфире полноэкранный ролик |
| `obs_connected` / `obs_live` | OBS-канал подключён / выведен в эфир |
| `out_volume` | текущая громкость мастер-выхода |
| `started_at` | unix-время старта (для аптайма) |
| `mediamtx` | пути и порты отдачи (HLS/RTSP/SRT/WebRTC) |

### Создание, изменение, удаление

| Метод | Путь | Ключевые параметры |
|---|---|---|
| POST | `/api/streams` | `name`, `input_url`, `output_url`, `out_w` (1920), `out_h` (1080), `banner_w` (1920), `banner_h` (150), `vcodec` (`h264_nvenc`), `vbitrate` (`6000k`), `fps` (25), `autostart` (0), `mediamtx_enabled` (1), `audio_tracks` (`0`) |
| PUT | `/api/streams/{sid}` | те же параметры |
| DELETE | `/api/streams/{sid}` | — |
| POST | `/api/streams/{sid}/start` | — |
| POST | `/api/streams/{sid}/stop` | — |

`audio_tracks` — индексы аудиодорожек входа через запятую. `0` — обычный
одноязычный режим. `0,1,2,3` — **мультиязык**: все дорожки уходят в MediaMTX
по SRT, реклама звучит одним общим звуком поверх всех языков.

> Изменение только `input_url` применяется **на лету**, без разрыва publish
> (в ответе будет `"seamless": true`). Изменение структурных параметров
> (разрешение, кодек, битрейт) требует перезапуска потока.

### Приём потока по SRT (внешний энкодер пушит нам)

Если источник умеет только SRT-caller (Astra Cesbo, аппаратные энкодеры), он
пушит **нам**, а слушаем мы. Приёмник — MediaMTX, путь заводится автоматически
по вашему `streamid`, настраивать его заранее не нужно.

```bash
# 1) узнать порт и шаблоны
curl -s $A/api/srtpush/info -H "X-API-Key: $KEY"

# 2) в энкодере указать (streamid придумываете сами):
#    srt://10.0.0.10:8890?streamid=publish:astra1

# 3) создать поток, читающий этот путь из MediaMTX по RTSP:
curl -s -X POST $A/api/streams -H "X-API-Key: $KEY" \
     -F "name=Канал с Astra" \
     -F "input_url=rtsp://127.0.0.1:8554/astra1"
```

`streamid` в энкодере и имя пути во входе совпадают. Допустимы латиница,
цифры, дефис и подчёркивание.

Проверить, что энкодер реально достучался:

```bash
curl -s http://127.0.0.1:9997/v3/paths/list | python3 -m json.tool
```

Путь должен быть в списке с `"ready": true`. Поле `tracks` покажет кодеки —
полезно, если картинка потом не пойдёт.

> Если в `tracks` значится `MPEG-1/2 Video`, читайте только по RTSP. Через
> SRT такой поток из MediaMTX не выйдет, а через HLS вернётся ошибка 500 —
> оба формата требуют H.264.

## 5. Эфирные действия

Это то, что вешают на кнопки пульта.

| Метод | Путь | Параметры | Описание |
|---|---|---|---|
| POST | `/api/streams/{sid}/play` | `banner_id`*, `duration` (30), `fade` (1.0), `x`,`y`,`w`,`h` | показать баннер |
| POST | `/api/streams/{sid}/playhtml` | `template_id`*, `duration` (30), `fade` (1.0), `x`,`y`,`w`,`h` | показать HTML-шаблон |
| POST | `/api/streams/{sid}/playvideo` | `video_id`* | полноэкранный ролик со звуком |
| POST | `/api/streams/{sid}/stopvideo` | — | снять ролик досрочно |
| POST | `/api/streams/{sid}/testcut` | `seconds` (20) | сымитировать обрыв входа (проверка буфера/заглушки) |

`*` — обязательный параметр.

- `duration` — сколько секунд держать на экране (1…3600).
- `fade` — плавное появление и исчезновение, секунд (0…10).
- `x, y, w, h` — точное размещение в пикселях кадра. Указывать нужно **все
  четыре** или ни одного; без них баннер занимает штатную баннерную зону с
  сохранением пропорций картинки.

Ролик и баннер — независимые слои: ролик перекрывает всё (он полноэкранный),
баннер/HTML/логотип накладываются поверх обычного эфира и поверх OBS-врезки.

## 6. Логотип и превью

| Метод | Путь | Параметры | Описание |
|---|---|---|---|
| POST | `/api/streams/{sid}/logo` | `banner_id`*, `x` (20), `y` (20), `w`, `h` | поставить постоянный логотип |
| DELETE | `/api/streams/{sid}/logo` | — | убрать логотип |
| POST | `/api/streams/{sid}/previewimg` | `banner_id`* | картинка плитки в мультивью (0 = убрать) |

Если заданы `w` и `h`, то `x`/`y` — **абсолютные** координаты в пикселях.
Без них работает режим «угол + отступ»: знак `x`/`y` выбирает угол кадра.

Настройки логотипа запоминаются **отдельно для каждого пресета входа** — при
переключении входа логотип восстанавливается в том виде, в каком вы его
настроили для этого источника.

## 7. Звук

| Метод | Путь | Параметры | Описание |
|---|---|---|---|
| POST | `/api/streams/{sid}/volume` | `out`, `ad` | громкость мастер-выхода и ролика |
| GET | `/api/streams/{sid}/levels` | — | текущие уровни для VU-метров (dB) |
| POST | `/api/streams/{sid}/obsvol` | `v`* | громкость OBS-врезки |

Значение громкости: `1.0` — без изменений, `0` — тишина, до `4.0` — усиление.

`/levels` отдаёт `out_rms`, `ad_rms`, `obs_rms`, `mic_rms` в децибелах
(`-100` — тишина). Метод безопасен для частого опроса.

## 8. OBS-наложение

Врезка живой картинки из OBS поверх эфира — двухшаговая, чтобы не выпускать
в эфир непроверенный сигнал.

```bash
# 1) подключиться (сигнал слышно и видно в превью, в эфире НИЧЕГО не меняется)
curl -s -X POST $A/api/streams/1/obs -H "X-API-Key: $KEY" \
     -F streamid=obs1 -F audio_mode=mute -F fade=0.6

# 2) выпустить в эфир (плавное появление)
curl -s -X POST $A/api/streams/1/obs/live -H "X-API-Key: $KEY"

# 3) снять и полностью отключить
curl -s -X POST $A/api/streams/1/obs/stop -H "X-API-Key: $KEY"
```

| Параметр | Значения | Смысл |
|---|---|---|
| `streamid` | любое имя | то же, что указано в OBS при публикации на MediaMTX |
| `audio_mode` | `mute` / `keep` | `mute` — слышно **только** OBS; `keep` — слышно **только** эфир (видео без звука OBS) |
| `fade` | секунды | длительность плавного появления/исчезновения |

В OBS публикация настраивается на
`srt://<агент>:8890?streamid=publish:obs1` (режим caller).

Если сигнала с OBS нет, `obs/live` вернёт ошибку и **не** будет глушить эфир
впустую.

## 9. Пресеты входов

Сохранённые источники для быстрого переключения канала на лету.

| Метод | Путь | Параметры |
|---|---|---|
| GET | `/api/streams/{sid}/presets` | — |
| POST | `/api/streams/{sid}/presets` | `name`*, `url`* |
| DELETE | `/api/streams/{sid}/presets/{pid}` | — |
| POST | `/api/streams/{sid}/presets/{pid}/activate` | — |
| POST | `/api/streams/{sid}/autofailover` | `enabled`* |

Переключение пресета идёт **без разрыва** выходного потока. Текущий вход, если
он не был сохранён, автоматически сохраняется как «Прежний вход» — вернуться
можно одним кликом. Вместе с входом восстанавливается и логотип этого пресета.

`autofailover` — автоматический переход на следующий пресет, если текущий
источник молчит дольше порога.

## 13. Микрофон (устаревшее)

Эндпоинты `/api/streams/{sid}/mic`, `/mic/stop`, `/micvol` сохранены для
совместимости, но карточка микрофона убрана из панели. Для комментария и
живых врезок используйте **OBS-наложение** (раздел 8) — оно даёт и звук, и
видео, и предпросмотр до выхода в эфир.

## 14. Подключение аппаратного пульта

Bitfocus Companion и Touch Portal умеют слать HTTP-запросы по нажатию кнопки —
этого достаточно, ничего дополнительно ставить не нужно.

**Bitfocus Companion**, модуль *Generic HTTP*:

| Поле | Значение |
|---|---|
| Method | `POST` |
| URL | `http://10.0.0.10:8500/api/streams/1/play` |
| Headers | `X-API-Key: ВАШ_КЛЮЧ` |
| Body type | `form-data` |
| Body | `banner_id=5`, `duration=15`, `fade=1` |

Одна кнопка — одно действие. Типовой набор для оператора:

| Кнопка | Запрос |
|---|---|
| Баннер «Реклама 1» | `POST /api/streams/1/play` + `banner_id=5&duration=15` |
| Баннер «Реклама 2» | `POST /api/streams/1/play` + `banner_id=6&duration=15` |
| Ролик | `POST /api/streams/1/playvideo` + `video_id=2` |
| Снять ролик | `POST /api/streams/1/stopvideo` |
| OBS в эфир | `POST /api/streams/1/obs/live` |
| OBS стоп | `POST /api/streams/1/obs/stop` |
| Заглушить эфир | `POST /api/streams/1/volume` + `out=0` |
| Вернуть звук | `POST /api/streams/1/volume` + `out=1` |

Обратную связь (подсветку кнопки) можно строить на опросе `GET /api/streams` —
поля `status.playing`, `status.ad_playing`, `status.obs_live`.

> Пульт обращается к агенту напрямую, минуя панель, поэтому он продолжит
> работать, даже если веб-панель недоступна.

## 15. Ограничения, о которых стоит знать

- **Один показ за раз.** Пока идёт баннер, повторный `/play` вернёт ошибку
  «баннер уже показывается». Ролик и баннер при этом независимы.
- **Порядок слоёв фиксирован**: эфир → OBS-врезка → баннер → логотип → HTML →
  ролик (сверху). Баннер и логотип видны поверх OBS-врезки.
- **`duration` считается от появления**, включая время fade.
- **Ключ один на весь агент** — разграничения прав по API нет. Ролики
  (`viewer`/`operator`/`admin`) действуют только в веб-панели.
